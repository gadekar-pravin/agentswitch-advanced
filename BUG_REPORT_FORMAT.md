# Bug report format

One report per finding. Send it to the course team as text (or as a file in your seat folder if it contains no platform data). Same fields every time:

| Field | What to write |
|---|---|
| Title | One line: what is wrong |
| Seat and login | e.g. 33, team33a |
| System | Suryodaya or Keystone |
| Date and time (IST) | When you saw it |
| Severity | High (data of another company, or a record changed without a person), Medium (wrong result), Low (cosmetic or unclear) |
| Steps | Numbered, exact. Another person must be able to repeat them |
| Expected | What should have happened |
| Actual | What did happen. Paste the message text. No passwords, tokens or customer data |
| Repeats | Every time, sometimes, once |
| Evidence | Request and response text, or a screenshot with nothing private in it |

Rules: read-only on live data. If a step would change or delete a record you did not create, stop and report the risk instead. Do not paste platform source code.
